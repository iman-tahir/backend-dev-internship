# Task Manager API — MongoDB Integration

REST API for managing tasks, built with Node.js, Express 5, MongoDB Atlas and Mongoose.

## Features

- Full CRUD operations for Tasks (Create, Read, Update, Delete)
- MongoDB Atlas cloud database integration using Mongoose
- Mongoose schema validation for required fields
- Task status validation using an enum: `pending`, `in-progress`, `done`
- Default task status set to `pending`
- Automatic MongoDB document IDs (`_id`)
- Automatic `createdAt` and `updatedAt` timestamps
- Centralized configuration using environment variables
- Validation errors handled with appropriate HTTP status codes
- MVC architecture with separate models, controllers and routes

## Setup

```bash
npm install
```

Create a `.env` file in the project root and configure your MongoDB connection string:

```env
MONGO_URI=your_mongodb_atlas_connection_string
PORT=5000
```

Start the development server:

```bash
npm run dev
```

Or start the server using:

```bash
npm start
```

Server runs on `http://localhost:5000`.

**Note:** Ensure your MongoDB Atlas cluster is running, your database credentials are correct, and your IP address is allowed in the Atlas network access settings. Never commit your `.env` file.

## Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/tasks` | Get all tasks |
| POST | `/api/tasks` | Create a new task |
| GET | `/api/tasks/:id` | Get a task by ID |
| PUT | `/api/tasks/:id` | Update a task |
| DELETE | `/api/tasks/:id` | Delete a task |
| GET | `/api/users` | Get users |

## Task fields

| Field | Type | Validation |
|---|---|---|
| `title` | String | Required |
| `status` | String | `pending`, `in-progress` or `done`; defaults to `pending` |
| `userId` | Number | Required |
| `_id` | ObjectId | Generated by MongoDB |
| `createdAt` | Date | Automatically generated |
| `updatedAt` | Date | Automatically generated |

## Example request

Create a task using `POST /api/tasks`:

```json
{
  "title": "Complete REST API integration",
  "status": "pending",
  "userId": 1
}
```

## Validation

- A missing `title` or `userId` is rejected by schema validation.
- Invalid task status values are rejected.
- Update operations use `runValidators: true` to enforce schema rules.
- Mongoose validation errors return `400 Bad Request`.
